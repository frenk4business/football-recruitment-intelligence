# v1.1 common-profile evaluation plan

Registered before expanded event ingestion/evaluation, 2026-10-01. This is separate from all frozen Phase 1–4 experiments. Provider-native versions are `statsbomb-profile-v2` and `wyscout-profile-v1`; common representation and method are `common-profile-v1` and `common-similarity-v1`.

1. Audit features using official event/tag specifications, equivalent-action synthetic tests, missingness and observed distributions. Start with open-play shots, open-play pass attempts/completion, geometric long passes, completed progressive passes, final-third entries and box entries. Omit any concept failing semantic/geometry/denominator checks. Pressures, carries, duels, tackles/interceptions, crosses and provider xG remain provider-specific unless independently justified. Freeze accepted definitions in an explicit manifest; log any deviations here.
2. Compare evidence thresholds 450/600/900 nominal reliable minutes. Search starts at 450; common eligibility is selected separately. For each provider/competition-season, order matches by date and ID, split at the median match, and evaluate same-identity retrieval from first-half to second-half profiles with at least half the threshold in each half. Isolate provider, competition-season and broad audited role family (DEF/MID/FWD). No cross-provider identity resolution; goalkeepers are excluded from common similarity.
3. Development strata are StatsBomb Premier League 2015/16 and Wyscout England 2017/18. Choose the smallest common threshold whose macro provider MRR reaches at least 90% of the best development-threshold MRR. Do not choose from the remaining leagues' outcomes. Publish every threshold, cohort size and missing role count. Remaining league/gender strata are transfer-of-method checks, not prospective external validation.
4. Use Euclidean distance on seven-or-fewer shared features, standardized using first-half development observations only. Report alternatives using provider-specific global and role/provider scalers, alongside raw and shared scaling. Do not choose a cross-provider normalisation merely because it hides provider differences. All neighbour ties resolve by provider-scoped profile ID. Within-provider candidate cohorts need at least 20 eligible profiles and adequate split-half evidence.
5. Report Recall@1/5/10, MRR, random-candidate expected MRR, query bootstrap intervals and match-resampling top-ten Jaccard stability. Report whether resampling covers both query and candidate uncertainty. Do not label descriptive similarity as performance, talent, transfer suitability or recommendation.
6. Audit provider bias with a fixed logistic-regression classifier and a held-out, provider-identity-grouped split, shared training-only scaling, class balancing, balanced accuracy and ROC AUC. No classifier tuning. Primary analysis uses men's profiles in the three shared league names, matching broad roles; secondary all-profile analysis exposes gender/coverage confounding. League/time/sample differences prevent causal attribution solely to provider. A held-out AUC or balanced accuracy above 0.75 withholds public cross-provider nearest-neighbour ranking. Descriptive common-feature comparison remains possible with the provider-effect caveat.
7. Publish provider/role distribution counts, mean/median/SD/quantiles and KS/Wasserstein distances; PCA coloured by provider; within- and cross-provider top-ten provider balance. Diagnostic results cannot establish accuracy, identity equivalence or causal measurement alignment. No neural/learned domain adaptation.
8. Existing Player DNA, historical translation and recruitment cohorts remain unchanged. Link their eligibility only through exact StatsBomb provider IDs and the original cohort manifests. Expanded candidates do not enter the Phase 4 shortlist.

Engineering gates: generated strict contracts and publication allowlist, <1 MB gzip search index, <50 KB detail, paginated 50 rows, typical search/filter <100 ms on documented hardware, bilingual accessible browser checks and existing route regressions. The static export budget may be revised explicitly based on measured additive derived payloads; it is not a reason to remove old frozen evidence.

Pre-evaluation semantic amendment: the official Wyscout dictionary has no separate kickoff pass subtype. Common passing features therefore include all passes and explicit pass restarts in both sources, rather than claiming equivalent open-play exclusions. Non-penalty shots include the explicit free-kick-shot subtype. The exact decisions are recorded in `provider-feature-semantics.md` before profile computation.

Availability-screen amendment (before a successful temporal/threshold or classifier run): the seven-candidate common vector yielded only 30 StatsBomb EPL profiles at 450 minutes, insufficient for the preregistered two-provider development cohorts. Unknown pass outcomes occurred legitimately in the source; no failure or success is imputed. `artifacts/v11/candidate-availability.json` records every scope before this decision. Following step 1's planned missingness screen, pass completion, completed progressive passes, completed final-third entries and completed box entries are excluded from `common-profile-v1`. The three accepted features are non-penalty shots, all pass attempts including restarts, and long pass attempts ≥30 m, all per nominal 90. Candidate geometry formulas remain tested and archived; no threshold or provider-bias outcomes informed this decision. Eligibility and unknown-value rules are unchanged. This is a deliberately low-dimensional descriptive representation, with limited style resolution.
