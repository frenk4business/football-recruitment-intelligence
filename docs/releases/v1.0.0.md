## Immutable release identity

The canonical release record is [GitHub v1.0.0](https://github.com/frenk4business/football-recruitment-intelligence/releases/tag/v1.0.0). Its annotated tag resolves to the final main/deployed commit; `git rev-parse 'v1.0.0^{commit}'` returns the exact SHA. The release body and attached `production-verification.json` record that SHA, Render deployment ID/status and completed live tests. The attached `release-manifest.json` independently binds that same SHA to public/build hashes and the deterministic commit timestamp; the [live manifest](https://football-recruitment-intelligence.onrender.com/release-manifest.json) identifies the currently deployed release.

A tracked file cannot contain its own final Git commit hash without changing that hash. Therefore the exact final identity and post-merge production evidence live in immutable tag/release assets, rather than a misleading self-referential hard-coded SHA or a post-tag documentation commit that moves main away from the tested release.
