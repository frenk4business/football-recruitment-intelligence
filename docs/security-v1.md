# Security review v1

Threat scope: a public static research site serving immutable release code and bounded aggregate JSON, without accounts, writable server APIs, contact forms or secrets. Primary risks are dependency compromise, mixed/stale releases, unsafe publication, malicious URL state, framing and untrusted client data. The origin/CDN and repository maintainer remain trusted; this is not a penetration-test certification.

Live header rules were applied to the existing service through the authorized Render API and verified by HTTP GET, not inferred from YAML. `config/http-headers.json` records the full policy. CSP allows same-origin scripts/styles/images/fonts/data, no objects, base URL, forms or framing; image data URLs are allowed. It contains no wildcard origin or unsafe-eval. Inline scripts remain allowed for the statically exported Next.js hydration/Flight payload; inline styles are required for chart/React presentation. Nonces would require per-request dynamic HTML, while maintaining hundreds of build-specific streamed-script hashes in external Dashboard headers would create a separate brittle deploy transaction. This documented exception preserves the preferred static architecture and is a residual injection-defense limitation, not a strict nonce-based CSP claim. There are no third-party script/font/form origins, Formspree, analytics or dynamic HTML injection features.

Referrer-Policy is strict-origin-when-cross-origin. Permissions-Policy disables camera, microphone, geolocation, payment and USB while leaving clipboard fallback usable. CSP frame-ancestors none protects against framing; nosniff protects MIME interpretation. Render supplies HSTS `max-age=315360000; includeSubdomains; preload`; this reports the observed provider header and does not assert this project independently enrolled a domain in the preload list. HTTPS is provider managed. No unnecessary cross-origin isolation or CORS relaxation is added.

Both locked dependency ecosystems are audited. A focused secret scan reviewed 38 reachable baseline commits and 2,423 unique blobs with no high-confidence private-key/provider-token matches; the release checkpoint is scanned again. This is pattern-based assurance, not proof of absence of arbitrary credentials. GitHub secret scanning/push protection are enabled. Never attach environment files or credentials to QA artifacts.

All published JSON is build-schema validated, hash-locked and runtime integrity checked before use. Runtime fetches enforce MIME, same-origin release paths, 3 MB bounds and 15-second timeout; malformed/stale/unknown versions cannot become ranked output. Query parsing rejects unsupported/duplicate/excessive inputs visibly. Release export rejects raw/database/posterior/map files. Local FastAPI binds loopback by the documented command; it is not deployed to Render.

Report an issue privately through GitHub's security reporting when available; otherwise contact the maintainer without posting secrets. Rotate any exposed credential first, remove it from releases/history as appropriate, then follow [operations](operations.md). Final audit commands and actual results are in [release QA](v1-release-qa.md).
