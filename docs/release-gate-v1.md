# v1.0 release gate — defined before implementation

Baseline: `29beb4d4462dda37b6ec0abca82ac904cef9620d`. Target `v1.0.0`. No release/tag until every required check below passes. Performance thresholds are defined here before implementation, not fitted to final results. Failures must be repaired or transparently deferred without calling the release complete.

## Required gates

1. `make test`: Python lint/format/type checks, unit/integration/parity tests, generated TS/JSON schema/OpenAPI checks; frontend lint/types/unit tests. Test Python 3.12 and 3.13. Node pinned to .node-version with locked npm/uv installs.
2. `make release-build` and `make release-validate`: schema/hash/allowlist/size checks for every public artifact; all seven scientific versions and frozen research outputs/plans/configurations match the baseline lock. No ingestion, fitting or final-data tuning in ordinary build/CI. Unpublished research cache not required.
3. Chromium, Firefox and WebKit: all existing 20 scenarios plus release-specific recovery, malformed/stale JSON, URL compatibility, navigation, keyboard, responsive, reduced-motion, clipboard/fallback and static metadata checks. No unexpected page errors, CSP violations or console errors in successful core journeys. Deliberate failure tests may emit expected network errors.
4. Accessibility: zero serious/critical automated violations in tested routes, manual code/DOM/keyboard review of core controls, visible focus, landmarks, names and announcements, accessible chart alternatives. 375px/768px/desktop and 200% zoom checks. Document review limitations; do not claim an assistive-technology or WCAG certification.
5. Performance: five representative routes `/`, `/player-dna/`, `/translation/`, `/recruitment/`, `/methodology/`, mobile profile from baseline, three cold runs per route. Median LCP <2.5s, every run CLS <0.1, median synthetic total blocking time <300ms; compressed initial JS <=250,000 bytes, decoded initial fetched JSON <=350,000 bytes, total initial transfer <=750,000 bytes. Observe five seconds after load; distinguish navigation prefetch from initial data. No eager robustness/all-player/PCA downloads. Largest single public JSON <=3,000,000 bytes; published JSON total <=25,000,000; static export <=50,000,000. Controlled recruitment input interaction settles <200ms median in the same CPU profile. These lab budgets do not claim field INP or real-device certification.
6. Security: live HTTPS, HSTS, nosniff, explicit CSP with no wildcards/unsafe-eval, frame-ancestors none, privacy referrer and camera/mic/geolocation restrictions. Static Next inline scripts may require a documented narrow unsafe-inline exception if hash/externalization is incompatible; test actual enforced policy in all engines. No external script/font/form services or permissive CORS added. Source maps/raw data/posteriors/credentials absent from export. Secret-pattern scan of tracked current tree and reachable history reviewed with limitations. npm/Python vulnerability audits have no unaddressed high/critical issue; all other findings triaged.
7. Deployment: same service, production branch main; required CI passed for final main; Render live SHA exactly equals final main; EN/NL route matrix HTTP200 plus rendered controls, every referenced asset loads, unknown routes real404 with recovery, headers/indexing/caching applied rather than only in YAML. Confirm service build/env/redirect settings to the extent connector permits and explicitly verify behavior.
8. Reproducibility: fresh checkout without data/raw, data/processed or local research caches; locked setup/test/release-build/validate pass. Compare public artifact and release-input digests; deterministic timestamp is commit time. Document framework/platform-generated output variability separately from scientific reproducibility. Old valid recruitment URL fixtures remain identical; malformed/unsupported state rejected visibly.
9. Documentation: audit issues resolved, README/index/architecture/limits/attribution/current version accurate; security/performance/accessibility/browser/reproducibility evidence, dependency/cache/contract policy, operations/incident/rollback instructions, checklist/changelog/release notes prepared. Rollback target is verified base deploy dep-daul9fo473hc739ojjlg. Separate Frenkkester.com repository untouched.
10. Merge only after PR CI and predeployment gates pass. Revalidate deployed main, then create annotated v1.0.0 tag and GitHub Release at that same SHA. Release manifest and GitHub release record exact final SHA; avoid a self-referential tracked commit hash. Tag workflow validates only and never deploys independently. No release while a required live setting is still pending.

## Evidence and execution

Audit checkpoint is committed before implementation. `docs/v1-release-qa.md` will map each gate to actual commands/results and audit resolutions. Machine-readable reports belong under `docs/releases/evidence/` when stable, or are attached to GitHub Release for exact final commit/build evidence. Production smoke is manually triggered and can be scheduled later; no paid monitoring or extra Render service is required. A retained CI run, observed live SHA, and downloadable release manifest make the final identity verifiable without moving main after the tag.
